# 闪暖日活校准 App

`shining-nikki-daily` 是一个用于《闪耀暖暖》日常任务流程整理、现场校准和操作能力测试的 Android 项目。

当前版本为 **v0.5.0 测试版**。App 通过悬浮窗逐步显示任务说明，由用户手动操作游戏，记录流程错误、缺失步骤、点击位置和不同分支，为后续自动化准备流程数据。**当前全流程引导尚未实现自动执行日常任务。**

## 功能

- **逐步引导**：选择任务后打开游戏，通过可拖动悬浮窗查看当前步骤、参考图片，支持上一步、下一步、暂停和结束。
- **现场纠错**：标记文字、顺序或操作位置错误，保存现场截图，完成流程后统一编辑备注。
- **插入和删除步骤**：在引导现场插入大流程、小步骤或删除当前步骤，编号自动顺延，并生成校准记录。
- **截图点选**：在原分辨率截图上点选目标，保存红圈标注、像素坐标、图片尺寸和相对坐标；已有步骤也可以补充点击位置。
- **分支记录**：框选分支判断区域，记录第二条操作路径，并分别标记两个分支的逻辑结束点。
- **记录导出**：导出 Markdown 和 JSON 汇总，连同截图用于后续整理流程。
- **能力测试**：保留控件树、截图、点击、滑动和返回等测试入口。

## 安装与使用

如已发布安装包，可在 [Releases](https://github.com/dongdong837/shining-nikki-daily/releases) 中下载对应版本的 `.apk` 文件。源码目录不保存 APK。

1. 在手机上安装 APK，打开“闪暖日活校准”。
2. 点击“打开无障碍设置”，启用 App 对应的无障碍服务。
3. 返回 App，点击“选择任务并开始引导”，勾选本次需要校准的任务。
4. 开始引导后，在游戏中把悬浮窗拖到合适位置。
5. 手动完成当前操作，再点击“下一步”；需要查看已有截图时点击“参考图”。
6. 发现错误时点击“标记有误”；缺少步骤或需要采集点击位置时使用“步骤校准”。
7. 引导完成后回到 App，进入“查看、编辑和导出校准记录”，补充备注并导出。

截图预览可点击查看清晰原图。校准记录采用分页和按需加载缩略图，避免同时加载大量原图。

逐步引导由用户手动完成，不会自动消费游戏资源；首页的点击、滑动等能力测试会执行相应操作，请在适合测试的画面使用。

## 记录分支流程

例如同一个任务页面可能出现“执行五次”按钮，也可能没有该按钮，可以记录两条路径：

1. 在分支出现前的步骤选择“在当前步骤后创建分支”，原有后续步骤作为分支1。
2. 在截图上框选分支2特有且稳定的按钮、标题或图标，作为判断条件。
3. 进入分支2，插入所需小步骤，并为操作补充点击位置。
4. 到达预期结束状态后点击“分支2结束”，引导会切回分支1起点。
5. 手动将游戏返回判断位置，完成分支1，再点击“分支1结束并汇合”。
6. 从汇合点继续下面的主流程。

汇合依据是相同的逻辑状态，例如回到联盟主页。两张结束截图中的人物、动画、数值可以不同，不要求整张图片完全一致。当前框选和分支记录用于采集数据，不代表已实现自动识别和选择分支。

## 导出文件

校准记录、增删记录、点击坐标、分支数据、原图和标注图保存在：

```text
/storage/emulated/0/Android/data/com.example.shiningprobe/files/Documents/guide-review
```

能力测试数据保存在：

```text
/storage/emulated/0/Android/data/com.example.shiningprobe/files/Documents/probe
```

以 App 首页显示的实际导出路径为准。完成校准后，可将导出目录复制到电脑，统一整理流程文档和图片。

## 从源码构建

### 环境

| 项目 | 当前配置 |
| --- | --- |
| 开发工具 | Android Studio |
| 开发语言 | Java，源码兼容级别 17 |
| Android Gradle Plugin | 9.2.0 |
| Gradle Wrapper | 9.4.1 |
| compileSdk / targetSdk | 36 |
| Build Tools | 36.0.0 |
| minSdk | 30（Android 11） |
| applicationId | `com.example.shiningprobe` |
| versionName / versionCode | 0.5.0 / 7 |

### 操作

1. 克隆整个仓库，保留流程文档、图片目录和 Android 工程的相对位置。
2. 在 Android Studio 中打开仓库内的 `ShiningProbe` 文件夹。
3. 安装工程需要的 SDK 组件，等待 Gradle 同步完成。
4. 选择 `app` 运行配置，连接手机后运行，或在 PowerShell 中构建：

```powershell
cd ShiningProbe
.\gradlew.bat assembleDebug
```

构建产物通常位于：

```text
ShiningProbe/app/build/outputs/apk/debug/app-debug.apk
```

首次构建需要联网下载 Gradle、插件及缺失的 SDK 组件。测试真机为 iQOO Neo10（V2425A），系统为 OriginOS 6 / Android 16；其他设备仍需实际验证。

## 仓库结构

```text
shining-nikki-daily/
├── README.md                 # 项目说明
├── LICENSE                   # MIT 许可证
├── .gitignore                # 忽略录屏、探测数据、APK 和构建缓存
├── 闪暖日活流程.md             # 日常任务流程源文档
├── 闪暖日活流程图片/           # 流程参考图片
└── ShiningProbe/             # Android Studio 工程
    ├── app/src/main/         # Java 源码、Manifest 和界面资源
    ├── app/build.gradle      # Android 配置与流程资源同步任务
    ├── gradle/wrapper/       # Gradle Wrapper
    └── gradlew.bat           # Windows 构建入口
```

构建时，`syncGuideAssets` 会读取 `ShiningProbe` 上一级目录中的 `闪暖日活流程.md` 和 `闪暖日活流程图片`，打包为 App 的流程与参考图。修改这些源文件后重新构建，即可更新 APK 内置流程。手机中新增的校准数据需要导出后再整理到仓库中。

## 开发状态

目前重点是校准日常任务流程，补齐截图、点击坐标、分支条件和汇合位置。仍需根据手机实际操作修正细节，完整自动执行能力属于后续开发内容。
